# 公共边界检测研究

本目录是独立研究代码，不导出到 npm 包入口，也不接入当前正式变形算法。

## 问题

两个图标视觉上大部分相似，SVG 却可能重新分割路径和孔洞。目标是稳定相同部分，只对差异部分做动画。完整 path 字符串相等无法覆盖这种场景。

## 当前原型

`analyzeSharedBoundaries(from, to, options)` 把曲线自适应采样为空间网格，按坐标距离及切线方向检测近似共边，并将命中的连续参数区间切回原始三次贝塞尔曲线。它可以跨 path、跨线段拆分及相反方向识别边界。

- 默认容差为 0.05 个图标坐标单位，最大采样步长 0.25，过滤短于 0.75 的孤立匹配。
- 使用原始曲线参数做 De Casteljau 分割；高亮片段仍是原曲线，不是重新拟合的图形。
- 不修改输入，不靠眼睛图标的名称、路径顺序或专门规则匹配。
- 有路径数量与采样预算，空图形和退化线段返回有限结果。

## 实测

Carbon 的 view / view-off（32×32）没有相同的完整 path。在默认参数下：

| 指标 | 结果 |
| --- | --- |
| 原图采样边界长度被覆盖比例 | 80.9% |
| 目标图采样边界长度被覆盖比例 | 65.8% |
| 原图公共片段数 | 22 |
| 目标图公共片段数 | 19 |

这些值是**采样边界长度**，不是图标面积、像素相似度或可以冻结的区域比例。只说明即使完整路径不同，仍可以检测到不少共边。文档页的研究面板可以调整容差观察结果。

## 尚未解决

1. 共边不等于可复用的填充面。同一边界可能属于外轮廓、孔洞或另一个覆盖层，必须同时确认填充规则与绘制顺序。
2. 一个原轮廓可能对应多个目标轮廓；现有一对一配对模型无法直接使用这些片段。
3. 锁定片段之后，差异片段的连接关系需要形成无交叉、保持孔洞的拓扑图；不能把一组锚点直接塞进等弧长配对。
4. 空间接近也可能是假匹配，特别是小间距平行边；容差和方向过滤不是语义识别。
5. 填充区域尚未实现“公共区域保持不动”的动画或性能结论。共边检测原型只检测、统计和高亮。

## 可播放的开放描边实验

`shared-stroke.mjs` 是独立的受限动画规划器，研究页提供直线、三次贝塞尔曲线、反向目标三个示例。原图 A→C 与目标 A→B 不要求 B 是原路径节点：先查找 B 的曲线参数，再用 De Casteljau 精确切开，保持 AB 的曲线坐标不变，只沿原轨迹收回 BC；反向播放则展开 BC。可通过进度滑块检查中间帧。

目前只接受一条开放描边与它的公共前缀（目标可反向绘制）。按有序弧长采样校验轨迹，拒绝只有交点、不同轨迹、闭合路径和多轮廓。固定片段来自较长路径的原始曲线；近似匹配仍受数值容差限制。这不是填充图标方案，也不是任意内部重合片段或多对多轮廓对应方案。

差异段使用曲线参数逐段截取，尚不保证跨线段匀速；只在研究页使用，没有改变 npm core、组件库或 Admin。研究测试验证固定片段在所有进度下完全一致、反向展开、曲线拆分和不支持输入的拒绝。

## 下一步实验

先用少量可信的共边建立单调、互不冲突的对应关系，保留无法对应区域的回退；再研究拆分、合并和孔洞的面级连接图。需要覆盖不同填充规则、多色、遮盖顺序、变换与中断的测试后，才能考虑接入正式 core。

运行 `pnpm test:research`。默认 `pnpm test` 也包含研究测试；当前正式 npm 包仍只发布 dist/。
